# CrowClaw v0.1.0-alpha.2

Alpha 2 adds a real local CrowQuant-compatible memory workflow to the standalone CrowClaw Windows desktop application. It preserves the verified Alpha 1 agent, persistence, approval, installation, and data-retaining uninstallation behavior.

## CrowQuant memory delivered

- remember user-entered text from CrowClaw's Memory surface;
- turn it into deterministic local lexical features, apply the CrowQuant randomized Walsh-Hadamard transform and Gaussian Lloyd-Max 4-bit quantization, and store the packed result in CrowClaw's SQLite database;
- query that memory locally and rank the nearest stored records using compressed vectors;
- retain stored memory and retrieval behavior across full application restarts;
- run natively inside CrowClaw without Python, a paid service, a remote account, a source checkout, or the separate CrowQuant repository;
- keep CrowQuant recall separate from CrowClaw's approved-action audit memory.

## Known Alpha limitations

- CrowQuant retrieval in Alpha 2 uses deterministic lexical features. It is not a neural embedding model, and the interface does not claim semantic-embedding behavior.
- Remember and recall are explicit controls in the Memory surface. The conversational agent does not yet invoke CrowQuant automatically; approval-gated agent-facing memory tools are the next integration boundary.
- A compatible model endpoint is still required for model-backed chat. CrowQuant memory itself is fully local and does not require that endpoint.
- Optional custom-endpoint API keys remain session-only and are not written to CrowClaw's SQLite database.
- Updates remain manual: download and run a newer verified installer.
